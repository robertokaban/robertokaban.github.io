Pendahuluan #

MySQL bukan sekadar tempat menyimpan data. Di balik perintah SELECT yang sederhana, terdapat arsitektur kompleks yang terdiri dari beberapa lapisan: koneksi client-server, parser query, optimizer, storage engine, dan lain-lain. Memahami arsitektur ini akan membantu Anda menulis query yang lebih efisien, memilih storage engine yang tepat, dan melakukan troubleshooting saat ada masalah.

Artikel ini membahas komponen utama MySQL serta konsep dasar database, table, row, dan column yang akan Anda gunakan sehari-hari.

Arsitektur Client-Server MySQL #

MySQL menggunakan model client-server. Ada dua pihak yang terlibat:

  • MySQL Server — proses yang berjalan di latar belakang (mysqld), bertugas menyimpan data, memproses query, dan mengelola akses.
  • MySQL Client — aplikasi yang terhubung ke server untuk mengirim perintah dan menerima hasil. Contoh: mysql CLI, MySQL Workbench, aplikasi PHP/Python/Node.js, dan sebagainya.

Komunikasi antara client dan server terjadi melalui protokol MySQL di atas koneksi TCP/IP (default port 3306) atau melalui socket file (pada koneksi lokal di Linux/macOS).

Alur Sederhana Sebuah Query #

  1. Client mengirim perintah SQL ke server melalui koneksi.
  2. Server menerima koneksi dan melakukan autentikasi (username, password, host).
  3. Parser memeriksa sintaks SQL.
  4. Optimizer menentukan cara eksekusi terbaik (misalnya index mana yang dipakai).
  5. Storage engine mengeksekusi pembacaan/penulisan data.
  6. Hasil dikirim kembali ke client.

Lapisan-Lapisan Internal MySQL #

Secara umum, arsitektur MySQL terbagi menjadi tiga lapisan besar:

1. Connection Layer (Lapisan Koneksi) #

Lapisan ini menangani koneksi masuk dari client. Setiap koneksi mendapat thread sendiri. Di sini terjadi:

  • Autentikasi user dan host.
  • Manajemen sesi (variabel sesi, SET, dll.).
  • Connection pooling (jika digunakan oleh aplikasi).

2. SQL Layer (Lapisan SQL) #

Lapisan ini adalah “otak” MySQL. Komponen pentingnya:

  • Query Parser — memecah query menjadi token dan membangun parse tree. Jika sintaks salah, error muncul di sini.
  • Preprocessor — memeriksa nama tabel, kolom, dan hak akses.
  • Query Optimizer — memilih execution plan terbaik: urutan join, index yang dipakai, dsb. Inilah sebabnya EXPLAIN berguna.
  • Query Cache — (deprecated di MySQL 8.0) dulu menyimpan hasil query yang sama.
  • Executor — menjalankan rencana yang sudah disusun, memanggil storage engine.

3. Storage Engine Layer (Lapisan Penyimpanan) #

Lapisan ini yang benar-benar menyentuh data di disk. MySQL mendukung pluggable storage engine, artinya Anda bisa memilih engine per tabel. Engine paling umum:

Storage Engine Karakteristik Cocok Untuk
InnoDB Default sejak MySQL 5.5; mendukung transaksi ACID, foreign key, row-level locking, crash recovery Aplikasi web, OLTP, hampir semua kasus umum
MyISAM Tidak mendukung transaksi; table-level locking; lebih cepat untuk read-heavy Arsip data, read-only, legacy
MEMORY Data disimpan di RAM; sangat cepat tapi hilang saat restart Tabel sementara, cache
CSV Menyimpan data sebagai file CSV Pertukaran data
ARCHIVE Kompresi tinggi; hanya insert & select Log, arsip historis

Rekomendasi: Gunakan InnoDB kecuali Anda punya alasan kuat untuk memilih engine lain. Hampir semua fitur modern (transaksi, foreign key, crash recovery) bergantung pada InnoDB.

Untuk melihat engine yang tersedia di server Anda:

SHOW ENGINES;

Untuk melihat engine yang dipakai sebuah tabel:

SHOW TABLE STATUS LIKE 'nama_tabel';

Konsep Dasar: Database, Table, Row, Column #

Sebelum masuk ke query, pahami dulu hierarki objek dalam MySQL:

Database (Schema) #

Database adalah wadah tertinggi yang menampung tabel-tabel. Dalam MySQL, istilah database dan schema sering dianggap sama. Satu server MySQL bisa memiliki banyak database.

CREATE DATABASE toko_online;
USE toko_online;

Table #

Table adalah struktur dua dimensi (baris × kolom) yang menyimpan data dengan tipe tertentu. Setiap tabel punya nama unik di dalam sebuah database.

CREATE TABLE pelanggan (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nama VARCHAR(100) NOT NULL,
  email VARCHAR(150) UNIQUE,
  dibuat_pada TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

Row (Baris / Record) #

Row adalah satu unit data lengkap dalam tabel. Misalnya satu pelanggan dengan semua atributnya.

INSERT INTO pelanggan (nama, email) VALUES ('Budi', 'budi@example.com');

Column (Kolom / Field) #

Column adalah atribut atau properti dari tabel. Setiap kolom punya tipe data yang menentukan nilai apa yang boleh disimpan.

Hubungan Antar Objek #

Server MySQL
└── Database (toko_online)
    ├── Table (pelanggan)
    │   ├── Column (id, nama, email, dibuat_pada)
    │   └── Row (1, 'Budi', 'budi@example.com', '2022-12-08 ...')
    └── Table (produk)
        └── ...

Tipe Data dalam MySQL #

Memilih tipe data yang tepat memengaruhi performa dan integritas data. Berikut kategori utama:

Tipe Numerik #

Tipe Keterangan
TINYINT 1 byte, -128 s.d. 127 (atau 0–255 unsigned)
INT / INTEGER 4 byte, paling umum untuk ID
BIGINT 8 byte, untuk angka sangat besar
DECIMAL(p,s) Angka desimal presisi, cocok untuk uang
FLOAT / DOUBLE Floating point, kurang presisi untuk uang

Tipe String #

Tipe Keterangan
CHAR(n) Panjang tetap, maks 255
VARCHAR(n) Panjang variabel, maks 65.535 (efektif lebih kecil)
TEXT Teks panjang (hingga 64 KB)
MEDIUMTEXT / LONGTEXT Teks sangat panjang

Tipe Tanggal & Waktu #

Tipe Keterangan
DATE Tanggal saja (YYYY-MM-DD)
TIME Waktu saja (HH:MM:SS)
DATETIME Tanggal + waktu, tanpa timezone
TIMESTAMP Tanggal + waktu, disimpan dalam UTC
YEAR Tahun 4 digit

Tipe Lain #

  • BOOLEAN — alias TINYINT(1).
  • ENUM('a','b') — pilihan terbatas.
  • JSON — menyimpan dokumen JSON (MySQL 5.7+).
  • BLOB — data biner (gambar, file).

Tips: Gunakan INT UNSIGNED AUTO_INCREMENT untuk primary key, VARCHAR untuk teks variabel, DECIMAL untuk uang, dan TIMESTAMP/DATETIME untuk waktu.

Melihat Struktur Database #

Beberapa perintah penting untuk menjelajahi struktur database:

-- Melihat daftar database
SHOW DATABASES;

-- Masuk ke database tertentu
USE toko_online;

-- Melihat daftar tabel
SHOW TABLES;

-- Melihat struktur tabel
DESCRIBE pelanggan;
-- atau
SHOW COLUMNS FROM pelanggan;

-- Melihat query pembuatan tabel
SHOW CREATE TABLE pelanggan;

Ringkasan #

  • MySQL menggunakan arsitektur client-server dengan tiga lapisan: connection, SQL, dan storage engine.
  • InnoDB adalah storage engine default dan direkomendasikan untuk hampir semua kasus.
  • Hierarki objek: Database → Table → Column & Row.
  • Memilih tipe data yang tepat penting untuk performa dan integritas data.
  • Perintah SHOW DATABASES, SHOW TABLES, dan DESCRIBE membantu Anda menjelajahi struktur database.

Pada artikel berikutnya, kita akan mulai menulis perintah SQL untuk membuat dan mengelola database serta tabel.
