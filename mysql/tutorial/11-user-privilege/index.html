Pendahuluan #

Sejauh ini kita selalu terhubung ke MySQL menggunakan user root. Padahal, menggunakan root untuk aplikasi sehari-hari adalah praktik yang sangat berbahaya — root memiliki akses tak terbatas, dan jika kredensialnya bocor, seluruh server bisa dikompromikan.

Praktik yang benar adalah principle of least privilege: setiap user hanya diberi hak akses seminimal mungkin yang dibutuhkan untuk tugasnya. Artikel ini membahas cara membuat user, memberikan privilege, mencabutnya, serta menggunakan role untuk manajemen yang lebih rapi.

Asumsi: Anda terhubung sebagai user dengan hak administratif (misalnya root) untuk menjalankan perintah di artikel ini.

Konsep Dasar: User, Host, dan Privilege #

Format User MySQL #

Di MySQL, user diidentifikasi oleh kombinasi username dan host:

'username'@'host'

Contoh:

  • 'app_user'@'localhost' — hanya bisa connect dari server lokal.
  • 'app_user'@'192.168.1.%' — bisa connect dari jaringan 192.168.1.x.
  • 'app_user'@'%' — bisa connect dari mana saja (kurang aman).

⚠️ Peringatan: 'user'@'%' membuka akses dari seluruh internet. Gunakan hanya jika benar-benar diperlukan dan server dilindungi firewall.

Tingkatan Privilege #

Privilege di MySQL bisa diberikan pada beberapa tingkatan:

Tingkatan Contoh Cakupan
Global ON *.* Semua database di server
Database ON toko_online.* Semua tabel di satu database
Tabel ON toko_online.produk Satu tabel tertentu
Kolom (nama, harga) Kolom tertentu dalam tabel
Routine ON PROCEDURE ... Stored procedure / function

Semakin spesifik tingkatan, semakin aman (least privilege).

Melihat User yang Ada #

SELECT user, host FROM mysql.user;

Atau untuk informasi lebih lengkap:

SELECT user, host, account_locked, password_expired FROM mysql.user;

Melihat privilege user tertentu:

SHOW GRANTS FOR 'app_user'@'localhost';

Membuat User Baru #

Sintaks #

CREATE USER 'username'@'host' IDENTIFIED BY 'password';

Contoh #

User untuk aplikasi lokal:

CREATE USER 'app_user'@'localhost' IDENTIFIED BY 'P@ssw0rdKuat!2022';

User untuk aplikasi dari jaringan tertentu:

CREATE USER 'app_user'@'192.168.1.%' IDENTIFIED BY 'P@ssw0rdKuat!2022';

Membuat beberapa user sekaligus:

CREATE USER
  'admin_toko'@'localhost' IDENTIFIED BY 'AdminP@ss!2022',
  'readonly_user'@'localhost' IDENTIFIED BY 'ReadOnlyP@ss!2022';

Opsi Tambahan #

Membatasi jumlah koneksi simultan:

CREATE USER 'app_user'@'localhost'
  IDENTIFIED BY 'P@ssw0rdKuat!2022'
  WITH MAX_CONNECTIONS_PER_HOUR 100
       MAX_USER_CONNECTIONS 10;

Membatasi sumber koneksi (MySQL 8.0.14+):

CREATE USER 'app_user'@'%'
  IDENTIFIED BY 'P@ssw0rdKuat!2022'
  REQUIRE CIPHER 'ECDHE-RSA-AES256-SHA384';

Mengubah Password User #

ALTER USER 'app_user'@'localhost' IDENTIFIED BY 'PasswordBaru!2022';

Untuk user yang sedang login:

ALTER USER USER() IDENTIFIED BY 'PasswordBaru!2022';

Menghapus User #

DROP USER 'app_user'@'localhost';

Atau dengan pengaman:

DROP USER IF EXISTS 'app_user'@'localhost';

Tips: Setelah DROP USER, privilege user tersebut otomatis dicabut. Tidak perlu REVOKE manual.

Memberikan Privilege dengan GRANT #

Sintaks #

GRANT privilege ON objek TO 'username'@'host';

Privilege Umum #

Privilege Kegunaan
ALL PRIVILEGES Semua hak (hati-hati!)
SELECT Membaca data
INSERT Menambah data
UPDATE Mengubah data
DELETE Menghapus data
CREATE Membuat tabel/database
DROP Menghapus tabel/database
ALTER Mengubah struktur
INDEX Membuat/menghapus index
CREATE VIEW Membuat view
SHOW VIEW Melihat definisi view
EXECUTE Menjalankan procedure/function
TRIGGER Membuat/menghapus trigger
CREATE USER Membuat user
GRANT OPTION Memberi hak ke user lain

Contoh 1: User Read-Only pada Satu Database #

GRANT SELECT ON toko_online.* TO 'readonly_user'@'localhost';

Hanya bisa membaca semua tabel di toko_online.

Contoh 2: User Aplikasi dengan CRUD Terbatas #

GRANT SELECT, INSERT, UPDATE, DELETE ON toko_online.* TO 'app_user'@'localhost';

Bisa membaca dan memodifikasi data, tetapi tidak bisa mengubah struktur (CREATE, DROP, ALTER).

Contoh 3: Privilege pada Tabel Tertentu #

GRANT SELECT, INSERT ON toko_online.pelanggan TO 'marketing_user'@'localhost';
GRANT SELECT ON toko_online.produk TO 'marketing_user'@'localhost';

marketing_user hanya bisa mengakses tabel pelanggan dan produk, bukan tabel lain.

Contoh 4: Privilege pada Kolom Tertentu #

GRANT SELECT (id, nama, email) ON toko_online.pelanggan TO 'support_user'@'localhost';

support_user hanya bisa membaca tiga kolom tersebut, bukan kolom telepon atau lainnya.

Contoh 5: Privilege Global (Hati-hati!) #

GRANT ALL PRIVILEGES ON *.* TO 'admin_user'@'localhost' WITH GRANT OPTION;

Memberi semua hak di semua database, plus kemampuan memberi hak ke user lain. Gunakan hanya untuk administrator tepercaya.

Contoh 6: Privilege untuk Menjalankan Procedure #

GRANT EXECUTE ON PROCEDURE toko_online.sp_semua_produk TO 'app_user'@'localhost';

Setelah GRANT: FLUSH PRIVILEGES? #

Jika Anda menggunakan perintah GRANT dan REVOKE (bukan memodifikasi tabel mysql.user secara langsung), FLUSH PRIVILEGES tidak diperlukan. MySQL otomatis memuat ulang privilege.

FLUSH PRIVILEGES hanya diperlukan jika Anda mengubah tabel grant secara langsung dengan INSERT/UPDATE/DELETE:

FLUSH PRIVILEGES;

Mencabut Privilege dengan REVOKE #

Sintaks #

REVOKE privilege ON objek FROM 'username'@'host';

Contoh #

Mencabut hak DELETE:

REVOKE DELETE ON toko_online.* FROM 'app_user'@'localhost';

Mencabut semua hak pada database:

REVOKE ALL PRIVILEGES ON toko_online.* FROM 'app_user'@'localhost';

Mencabut GRANT OPTION:

REVOKE GRANT OPTION ON toko_online.* FROM 'admin_user'@'localhost';

Melihat Privilege Setelah REVOKE #

SHOW GRANTS FOR 'app_user'@'localhost';

Role: Manajemen Privilege yang Lebih Rapi #

Role adalah kumpulan privilege yang bisa diberikan ke banyak user. Ini menghindari pengulangan GRANT untuk setiap user dengan kebutuhan yang sama. Role didukung sejak MySQL 8.0.

Membuat Role #

CREATE ROLE 'role_readonly';
CREATE ROLE 'role_app';
CREATE ROLE 'role_admin';

Memberikan Privilege ke Role #

-- Role read-only
GRANT SELECT ON toko_online.* TO 'role_readonly';

-- Role aplikasi (CRUD)
GRANT SELECT, INSERT, UPDATE, DELETE ON toko_online.* TO 'role_app';

-- Role admin (semua + grant option)
GRANT ALL PRIVILEGES ON toko_online.* TO 'role_admin' WITH GRANT OPTION;

Memberikan Role ke User #

GRANT 'role_app' TO 'app_user'@'localhost';
GRANT 'role_readonly' TO 'report_user'@'localhost';
GRANT 'role_admin' TO 'admin_toko'@'localhost';

Mengaktifkan Role #

Setelah role diberikan, user harus mengaktifkannya agar privilege berlaku:

-- Login sebagai app_user, lalu:
SET DEFAULT ROLE 'role_app' TO 'app_user'@'localhost';

Atau aktifkan untuk sesi saat ini:

SET ROLE 'role_app';

Melihat role yang aktif:

SELECT CURRENT_ROLE();

Mencabut Role dari User #

REVOKE 'role_app' FROM 'app_user'@'localhost';

Menghapus Role #

DROP ROLE IF EXISTS 'role_readonly';

Melihat Daftar Role #

SELECT * FROM mysql.role_edges;

Atau:

SHOW GRANTS FOR 'role_app';

Best Practice Keamanan #

1. Jangan Gunakan root untuk Aplikasi #

Buat user khusus untuk setiap aplikasi dengan privilege minimal:

CREATE USER 'webapp_toko'@'localhost' IDENTIFIED BY 'P@ssw0rdKuat!2022';
GRANT SELECT, INSERT, UPDATE, DELETE ON toko_online.* TO 'webapp_toko'@'localhost';

2. Batasi Host #

Gunakan localhost atau IP spesifik, bukan %:

-- Baik
CREATE USER 'app_user'@'192.168.1.10' IDENTIFIED BY '...';

-- Hindari (kecuali perlu)
CREATE USER 'app_user'@'%' IDENTIFIED BY '...';

3. Gunakan Password Kuat #

  • Minimal 12 karakter.
  • Kombinasi huruf besar, kecil, angka, dan simbol.
  • Jangan gunakan password yang sama dengan layanan lain.

MySQL 8 memiliki validate_password component yang bisa diaktifkan:

INSTALL COMPONENT 'file://component_validate_password';

-- Cek kebijakan
SHOW VARIABLES LIKE 'validate_password%';

-- Set kebijakan kuat
SET GLOBAL validate_password.policy = 'STRONG';
SET GLOBAL validate_password.length = 12;

4. Pisahkan User Berdasarkan Peran #

  • app_readonly — untuk laporan/analitik.
  • app_write — untuk aplikasi yang menulis data.
  • app_migration — untuk migrasi skema (privilege ALTER, CREATE, DROP).
  • admin — untuk administrator, hanya digunakan saat perlu.

5. Audit User Secara Berkala #

-- Melihat user yang tidak pernah login
SELECT user, host, last_login FROM mysql.user
WHERE last_login IS NULL OR last_login < NOW() - INTERVAL 90 DAY;

Hapus user yang tidak lagi digunakan:

DROP USER 'user_lama'@'localhost';

6. Batasi Akses ke Tabel Sensitif #

Untuk tabel berisi data pribadi (misalnya pelanggan), berikan akses kolom saja:

GRANT SELECT (id, nama, email) ON toko_online.pelanggan TO 'support_user'@'localhost';

7. Gunakan SSL/TLS untuk Koneksi Remote #

CREATE USER 'remote_user'@'%'
  IDENTIFIED BY 'P@ssw0rdKuat!2022'
  REQUIRE SSL;

Atau wajibkan cipher tertentu:

ALTER USER 'remote_user'@'%' REQUIRE CIPHER 'ECDHE-RSA-AES256-SHA384';

8. Log Aktivitas Penting #

Aktifkan general query log atau audit plugin (MySQL Enterprise) untuk memantau query yang dijalankan:

SET GLOBAL general_log = 'ON';
SET GLOBAL general_log_file = '/var/log/mysql/general.log';

⚠️ Peringatan: General log bisa sangat besar dan memperlambat server. Aktifkan hanya untuk debugging jangka pendek.

Contoh Lengkap: Setup User untuk Aplikasi Toko Online #

Berikut skenario lengkap membuat user untuk berbagai kebutuhan aplikasi toko_online:

-- 1. User untuk aplikasi web (CRUD data)
CREATE USER 'webapp_toko'@'localhost' IDENTIFIED BY 'WebAppP@ss!2022';
GRANT SELECT, INSERT, UPDATE, DELETE ON toko_online.* TO 'webapp_toko'@'localhost';

-- 2. User untuk laporan/analitik (read-only)
CREATE USER 'report_toko'@'localhost' IDENTIFIED BY 'ReportP@ss!2022';
GRANT SELECT ON toko_online.* TO 'report_toko'@'localhost';

-- 3. User untuk migrasi skema (privilege struktur)
CREATE USER 'migrate_toko'@'localhost' IDENTIFIED BY 'MigrateP@ss!2022';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, ALTER, INDEX,
      CREATE VIEW, SHOW VIEW, TRIGGER, EXECUTE
ON toko_online.* TO 'migrate_toko'@'localhost';

-- 4. User admin (untuk DBA)
CREATE USER 'admin_toko'@'localhost' IDENTIFIED BY 'AdminP@ss!2022';
GRANT ALL PRIVILEGES ON toko_online.* TO 'admin_toko'@'localhost' WITH GRANT OPTION;

-- 5. User support (hanya baca data pelanggan terbatas)
CREATE USER 'support_toko'@'localhost' IDENTIFIED BY 'SupportP@ss!2022';
GRANT SELECT (id, nama, email) ON toko_online.pelanggan TO 'support_toko'@'localhost';
GRANT SELECT ON toko_online.pesanan TO 'support_toko'@'localhost';

-- Verifikasi
SHOW GRANTS FOR 'webapp_toko'@'localhost';
SHOW GRANTS FOR 'report_toko'@'localhost';

Menguji Akses #

Login sebagai webapp_toko:

mysql -u webapp_toko -p toko_online

Coba query:

-- Berhasil (punya SELECT)
SELECT * FROM produk;

-- Berhasil (punya INSERT)
INSERT INTO pelanggan (nama, email) VALUES ('Test', 'test@example.com');

-- GAGAL (tidak punya CREATE)
CREATE TABLE test_table (id INT);
-- ERROR 1142 (42000): CREATE command denied to user 'webapp_toko'@'localhost'

Ringkasan #

Perintah Fungsi
CREATE USER Membuat user baru
ALTER USER Mengubah password / properti user
DROP USER Menghapus user
GRANT Memberikan privilege
REVOKE Mencabut privilege
SHOW GRANTS Melihat privilege user
CREATE ROLE Membuat role (kumpulan privilege)
SET DEFAULT ROLE Mengaktifkan role untuk user
SET ROLE Mengaktifkan role untuk sesi saat ini

Poin penting:

  • User diidentifikasi oleh 'username'@'host'.
  • Terapkan principle of least privilege — beri hak seminimal mungkin.
  • Jangan gunakan root untuk aplikasi.
  • Gunakan role untuk mengelola privilege banyak user dengan rapi.
  • FLUSH PRIVILEGES hanya diperlukan jika memodifikasi tabel grant secara langsung.
  • Batasi host, gunakan password kuat, dan audit user secara berkala.
