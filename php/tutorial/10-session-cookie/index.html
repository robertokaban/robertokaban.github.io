Pendahuluan #

HTTP adalah protokol stateless — setiap request berdiri sendiri, server tidak otomatis mengingat request sebelumnya. Padahal aplikasi web sering perlu mengingat user: siapa yang login, apa isi keranjang belanja, preferensi tema, dan sebagainya.

Dua mekanisme utama untuk menyimpan state:

  • Cookie — data kecil yang disimpan di browser dan dikirim ke server setiap request.
  • Session — data yang disimpan di server, diidentifikasi oleh session ID yang biasanya disimpan di cookie.

Artikel ini membahas cara kerja keduanya, perbedaannya, keamanan, dan best practice.

Asumsi: Anda sudah memahami superglobal, form handling, dan fungsi PHP dari artikel sebelumnya.

Cookie #

Cookie adalah data kecil (maksimal sekitar 4 KB) yang disimpan di browser dan dikirim ke server pada setiap request ke domain yang sama.

Cara Kerja Cookie #

  1. Server mengirim header Set-Cookie dalam response.
  2. Browser menyimpan cookie.
  3. Pada request berikutnya ke domain yang sama, browser mengirim cookie dalam header Cookie.
# Response dari server
Set-Cookie: tema=dark; Path=/; Max-Age=86400; HttpOnly

# Request berikutnya dari browser
Cookie: tema=dark

Membuat Cookie di PHP #

Gunakan setcookie() — harus dipanggil sebelum ada output apa pun (termasuk spasi atau HTML).

<?php
// setcookie(nama, nilai, expires, path, domain, secure, httponly)

setcookie("tema", "dark", [
    "expires" => time() + 86400,  // 1 hari
    "path" => "/",
    "domain" => "",
    "secure" => true,             // hanya via HTTPS
    "httponly" => true,           // tidak bisa diakses JavaScript
    "samesite" => "Lax",          // perlindungan CSRF
]);

Sintaks lama (sebelum PHP 7.3):

<?php
setcookie("tema", "dark", time() + 86400, "/", "", true, true);

Tips: Gunakan sintaks array (PHP 7.3+) — lebih jelas dan mendukung SameSite.

Membaca Cookie #

Cookie tersedia di superglobal $_COOKIE.

<?php
$tema = $_COOKIE["tema"] ?? "light";
echo "Tema: $tema";

Menghapus Cookie #

Set cookie dengan nilai kosong dan expires di masa lalu:

<?php
setcookie("tema", "", [
    "expires" => time() - 3600,
    "path" => "/",
]);

Catatan: Atribut path dan domain harus sama dengan saat cookie dibuat agar penghapusan berhasil.

Atribut Cookie #

Atribut Arti Rekomendasi
expires Kapan cookie kedaluwarsa Set sesuai kebutuhan
path Path yang bisa mengakses cookie / untuk seluruh situs
domain Domain yang bisa mengakses cookie Kosongkan untuk current domain
secure Hanya dikirim via HTTPS Aktifkan di produksi
httponly Tidak bisa diakses JavaScript Aktifkan untuk cookie sensitif
samesite Kontrol pengiriman lintas situs Lax (default) atau Strict

SameSite — Perlindungan CSRF #

Nilai Perilaku
Strict Cookie tidak dikirim pada request lintas situs
Lax Cookie dikirim pada navigasi top-level (klik link), tidak pada request POST lintas situs
None Cookie selalu dikirim (wajib Secure) 
<?php
setcookie("session_id", $id, [
    "secure" => true,
    "httponly" => true,
    "samesite" => "Strict",
]);

Rekomendasi: Gunakan SameSite=Lax sebagai default. Gunakan Strict untuk cookie yang sangat sensitif (misalnya session admin).

Kapan Menggunakan Cookie? #

  • Preferensi user yang perlu diketahui server (tema, bahasa).
  • Remember me — token untuk auto-login.
  • Tracking (analytics) — biasanya pihak ketiga.
  • Session ID — biasanya dikelola otomatis oleh PHP.

⚠️ Peringatan: Jangan simpan data sensitif (password, token rahasia) di cookie — cookie bisa dibaca user dan penyerang.

Session #

Session menyimpan data di server, diidentifikasi oleh session ID yang biasanya disimpan di cookie.

Cara Kerja Session #

  1. session_start() dipanggil — PHP membuat session ID unik (jika belum ada).
  2. PHP mengirim cookie PHPSESSID ke browser.
  3. Data session disimpan di file server (default: /tmp/sess_XXXX).
  4. Pada request berikutnya, browser mengirim cookie PHPSESSID — PHP memuat data session yang sesuai.
# Response dari server
Set-Cookie: PHPSESSID=abc123def456; Path=/; HttpOnly

# Request berikutnya
Cookie: PHPSESSID=abc123def456

Memulai Session #

session_start() harus dipanggil di awal setiap file yang menggunakan session — sebelum output apa pun.

<?php
session_start();

// Sekarang $_SESSION tersedia
$_SESSION["user_id"] = 1;
$_SESSION["user_nama"] = "Budi";

Peringatan: Jika ada output (termasuk spasi atau newline) sebelum session_start(), akan muncul error “Headers already sent”. Pastikan <?php adalah hal pertama di file, tanpa spasi atau BOM.

Mengakses Data Session #

<?php
session_start();

// Baca
$nama = $_SESSION["user_nama"] ?? "Tamu";
echo "Halo, $nama!";

// Cek apakah user login
if (isset($_SESSION["user_id"])) {
    echo "Anda sudah login";
} else {
    echo "Silakan login";
}

Mengubah Data Session #

<?php
session_start();

$_SESSION["keranjang"] = [
    ["id" => 1, "nama" => "Keyboard", "jumlah" => 2],
];

// Tambah item
$_SESSION["keranjang"][] = ["id" => 2, "nama" => "Mouse", "jumlah" => 1];

// Ubah
$_SESSION["user_nama"] = "Budi Santoso";

Menghapus Data Session #

<?php
session_start();

// Hapus satu key
unset($_SESSION["keranjang"]);

// Hapus semua data (session tetap aktif)
$_SESSION = [];

// Hapus cookie session di browser
if (ini_get("session.use_cookies")) {
    $params = session_get_cookie_params();
    setcookie(
        session_name(),
        "",
        time() - 42000,
        $params["path"],
        $params["domain"],
        $params["secure"],
        $params["httponly"]
    );
}

// Hancurkan session di server
session_destroy();

Tips: Untuk logout, lakukan ketiganya: $_SESSION = [], hapus cookie, dan session_destroy().

Session ID #

<?php
session_start();

// Mendapatkan session ID
echo session_id();

// Mendapatkan nama session (default: PHPSESSID)
echo session_name();

Regenerasi Session ID #

Wajib dilakukan setelah login untuk mencegah session fixation — penyerang yang mengetahui session ID sebelum login bisa membajak session setelah user login.

<?php
session_start();

// Setelah login berhasil
if ($loginBerhasil) {
    session_regenerate_id(true);  // true = hapus session lama
    $_SESSION["user_id"] = $user["id"];
    $_SESSION["user_nama"] = $user["nama"];
}

Peringatan: Selalu panggil session_regenerate_id(true) setelah login, logout, atau perubahan hak akses.

Konfigurasi Session #

Konfigurasi session ada di php.ini atau bisa diubah via ini_set() sebelum session_start().

Konfigurasi Penting #

; Nama cookie session
session.name = PHPSESSID

; Masa hidup session (detik)
session.gc_maxlifetime = 1440

; Path cookie session
session.cookie_path = /

; Domain cookie session
session.cookie_domain =

; Hanya via HTTPS
session.cookie_secure = 1

; Tidak bisa diakses JavaScript
session.cookie_httponly = 1

; SameSite cookie
session.cookie_samesite = Lax

; Gunakan hanya cookie (jangan URL)
session.use_only_cookies = 1

; Jangan terima session ID dari URL
session.use_trans_sid = 0

; Regenerasi ID otomatis
session.use_strict_mode = 1

Rekomendasi keamanan: Setidaknya aktifkan session.cookie_httponly = 1, session.cookie_secure = 1 (di produksi), session.use_only_cookies = 1, dan session.use_strict_mode = 1.

Mengubah Konfigurasi via PHP #

<?php
// HARUS sebelum session_start()
ini_set("session.cookie_httponly", "1");
ini_set("session.cookie_secure", "1");
ini_set("session.cookie_samesite", "Lax");
ini_set("session.use_only_cookies", "1");
ini_set("session.use_strict_mode", "1");

session_start();

Penyimpanan Session #

Secara default, PHP menyimpan session di file (/tmp/sess_XXXX). Untuk aplikasi produksi dengan banyak server, pertimbangkan:

  • Database — simpan session di tabel MySQL.
  • Redis atau Memcached — cepat dan mendukung banyak server.
  • Filesystem kustom — dengan session.save_path.
<?php
// Simpan session di folder kustom
ini_set("session.save_path", "/var/www/sessions");
session_start();

Perbandingan Session dan Cookie #

Aspek Session Cookie
Lokasi data Server Browser
Kapasitas Tidak terbatas (tergantung server) ~4 KB per cookie
Keamanan Lebih aman — data tidak terlihat user Bisa dibaca user
Dikirim ke server Hanya session ID Semua data cookie
Masa hidup Tergantung konfigurasi server Bisa diatur (expires)
Cocok untuk Data login, keranjang, data sensitif Preferensi, remember me, tracking
Dampak performa Sedikit (baca file/DB) Tidak ada (selain ukuran request)

Rekomendasi: Gunakan session untuk data sensitif dan data yang perlu diakses server. Gunakan cookie untuk preferensi yang perlu bertahan lama atau diketahui server.

Keamanan Session dan Cookie #

1. Session Fixation #

Serangan: Penyerang memberikan session ID yang diketahui ke korban. Setelah korban login, penyerang menggunakan session ID yang sama untuk mengakses akun korban.

Solusi:

<?php
// Setelah login berhasil
session_regenerate_id(true);

Aktifkan juga session.use_strict_mode = 1 — PHP menolak session ID yang tidak dikenal.

2. Session Hijacking #

Serangan: Penyerang mencuri session ID (via XSS, sniffing, atau malware) dan menggunakannya untuk mengakses akun korban.

Solusi:

  • Gunakan HTTPS — mencegah sniffing.
  • Set session.cookie_httponly = 1 — mencegah akses via JavaScript (XSS).
  • Set session.cookie_secure = 1 — cookie hanya via HTTPS.
  • Regenerasi session ID secara berkala.
  • Bind session ke IP atau user agent (opsional, bisa menyebabkan masalah dengan mobile).
<?php
session_start();

// Bind session ke user agent (opsional)
$userAgent = $_SERVER["HTTP_USER_AGENT"] ?? "";
if (!isset($_SESSION["user_agent"])) {
    $_SESSION["user_agent"] = $userAgent;
} elseif ($_SESSION["user_agent"] !== $userAgent) {
    // User agent berubah — kemungkinan session hijacking
    session_destroy();
    die("Session tidak valid");
}

3. XSS (Cross-Site Scripting) #

Serangan: Penyerang menyisipkan JavaScript berbahaya yang mencuri cookie.

Solusi:

  • Selalu htmlspecialchars() saat output ke HTML.
  • Set HttpOnly pada cookie session — JavaScript tidak bisa membaca cookie.
  • Implementasikan Content Security Policy (CSP).

4. CSRF (Cross-Site Request Forgery) #

Serangan: Penyerang membuat user yang sudah login mengirim request tanpa sadar.

Solusi:

  • Set SameSite=Lax atau Strict pada cookie session.
  • Implementasikan CSRF token (dibahas di artikel sebelumnya).

5. Session Timeout #

Solusi: Terapkan timeout untuk session yang tidak aktif.

<?php
session_start();

$timeout = 1800; // 30 menit
if (isset($_SESSION["last_activity"])) {
    if (time() - $_SESSION["last_activity"] > $timeout) {
        session_unset();
        session_destroy();
        header("Location: login.php?pesan=timeout");
        exit;
    }
}
$_SESSION["last_activity"] = time();

6. Secure Cookie Attributes #

Selalu set atribut keamanan pada cookie session:

<?php
session_set_cookie_params([
    "lifetime" => 0,           // session cookie (hilang saat browser ditutup)
    "path" => "/",
    "domain" => "",
    "secure" => true,          // hanya HTTPS
    "httponly" => true,        // tidak bisa diakses JS
    "samesite" => "Lax",       // perlindungan CSRF
]);

session_start();

Tips: Panggil session_set_cookie_params() sebelum session_start().

Ringkasan Keamanan #

Ancaman Solusi
Session fixation session_regenerate_id(true) setelah login
Session hijacking HTTPS, HttpOnly, Secure, regenerasi ID
XSS htmlspecialchars(), HttpOnly, CSP
CSRF SameSite, CSRF token
Session timeout Cek last_activity
Cookie theft Secure, HttpOnly, SameSite

Contoh Praktis #

1. Login dan Logout dengan Session #

login.php:

<?php
session_start();

// Jika sudah login, redirect ke dashboard
if (isset($_SESSION["user_id"])) {
    header("Location: dashboard.php");
    exit;
}

$error = "";

if ($_SERVER["REQUEST_METHOD"] === "POST") {
    $email = filter_var($_POST["email"] ?? "", FILTER_VALIDATE_EMAIL);
    $password = $_POST["password"] ?? "";

    if ($email === false || $password === "") {
        $error = "Email dan password wajib diisi";
    } else {
        // Cek ke database
        $pdo = new PDO("mysql:host=localhost;dbname=toko", "root", "");
        $stmt = $pdo->prepare("SELECT id, nama, password FROM users WHERE email = ?");
        $stmt->execute([$email]);
        $user = $stmt->fetch(PDO::FETCH_ASSOC);

        if ($user && password_verify($password, $user["password"])) {
            // Login berhasil
            session_regenerate_id(true);  // PENTING!
            $_SESSION["user_id"] = $user["id"];
            $_SESSION["user_nama"] = $user["nama"];
            $_SESSION["last_activity"] = time();

            header("Location: dashboard.php");
            exit;
        } else {
            $error = "Email atau password salah";
        }
    }
}
?>

<form method="post">
    <?php if ($error): ?>
        <div class="error"><?= htmlspecialchars($error) ?></div>
    <?php endif; ?>
    <input type="email" name="email" placeholder="Email" required>
    <input type="password" name="password" placeholder="Password" required>
    <button type="submit">Login</button>
</form>

dashboard.php:

<?php
session_start();

// Cek login
if (!isset($_SESSION["user_id"])) {
    header("Location: login.php");
    exit;
}

// Cek timeout
$timeout = 1800;
if (isset($_SESSION["last_activity"]) && time() - $_SESSION["last_activity"] > $timeout) {
    session_unset();
    session_destroy();
    header("Location: login.php?pesan=timeout");
    exit;
}
$_SESSION["last_activity"] = time();

$nama = $_SESSION["user_nama"];
?>

<h1>Selamat datang, <?= htmlspecialchars($nama) ?>!</h1>
<a href="logout.php">Logout</a>

logout.php:

<?php
session_start();

// Hapus semua data session
$_SESSION = [];

// Hapus cookie session
if (ini_get("session.use_cookies")) {
    $params = session_get_cookie_params();
    setcookie(
        session_name(),
        "",
        time() - 42000,
        $params["path"],
        $params["domain"],
        $params["secure"],
        $params["httponly"]
    );
}

// Hancurkan session
session_destroy();

header("Location: login.php");
exit;

2. Remember Me dengan Cookie #

<?php
// Saat login
if ($loginBerhasil && !empty($_POST["remember"])) {
    $token = bin2hex(random_bytes(32));
    $hash = hash("sha256", $token);

    // Simpan hash ke database
    $stmt = $pdo->prepare("UPDATE users SET remember_token = ? WHERE id = ?");
    $stmt->execute([$hash, $user["id"]]);

    // Set cookie
    setcookie("remember_token", $token, [
        "expires" => time() + (30 * 24 * 60 * 60),  // 30 hari
        "path" => "/",
        "secure" => true,
        "httponly" => true,
        "samesite" => "Lax",
    ]);
}

// Saat halaman dimuat — cek auto-login
if (!isset($_SESSION["user_id"]) && isset($_COOKIE["remember_token"])) {
    $token = $_COOKIE["remember_token"];
    $hash = hash("sha256", $token);

    $stmt = $pdo->prepare("SELECT id, nama FROM users WHERE remember_token = ?");
    $stmt->execute([$hash]);
    $user = $stmt->fetch(PDO::FETCH_ASSOC);

    if ($user) {
        session_regenerate_id(true);
        $_SESSION["user_id"] = $user["id"];
        $_SESSION["user_nama"] = $user["nama"];
    }
}

Tips: Simpan hash token di database, bukan token asli. Jika database bocor, token tidak bisa digunakan penyerang.

3. Keranjang Belanja dengan Session #

<?php
session_start();

// Tambah item ke keranjang
function tambahKeKeranjang(int $produkId, string $nama, float $harga, int $jumlah = 1): void {
    if (!isset($_SESSION["keranjang"])) {
        $_SESSION["keranjang"] = [];
    }

    // Cek apakah produk sudah ada
    foreach ($_SESSION["keranjang"] as $key => $item) {
        if ($item["id"] === $produkId) {
            $_SESSION["keranjang"][$key]["jumlah"] += $jumlah;
            return;
        }
    }

    // Tambah item baru
    $_SESSION["keranjang"][] = [
        "id" => $produkId,
        "nama" => $nama,
        "harga" => $harga,
        "jumlah" => $jumlah,
    ];
}

// Hitung total
function totalKeranjang(): float {
    $total = 0;
    foreach ($_SESSION["keranjang"] ?? [] as $item) {
        $total += $item["harga"] * $item["jumlah"];
    }
    return $total;
}

// Contoh penggunaan
tambahKeKeranjang(1, "Keyboard", 450000, 2);
tambahKeKeranjang(2, "Mouse", 150000, 1);

echo "Total: Rp" . number_format(totalKeranjang(), 0, ",", ".");
// "Total: Rp1.050.000"

4. Flash Message #

Flash message adalah pesan yang hanya muncul sekali (misalnya setelah redirect).

<?php
session_start();

// Set flash message
function setFlash(string $tipe, string $pesan): void {
    $_SESSION["flash"] = ["tipe" => $tipe, "pesan" => $pesan];
}

// Ambil dan hapus flash message
function getFlash(): ?array {
    if (isset($_SESSION["flash"])) {
        $flash = $_SESSION["flash"];
        unset($_SESSION["flash"]);
        return $flash;
    }
    return null;
}

// Contoh: setelah simpan data
setFlash("sukses", "Data berhasil disimpan");
header("Location: index.php");
exit;

// Di index.php
$flash = getFlash();
if ($flash):
?>
    <div class="alert alert-<?= htmlspecialchars($flash["tipe"]) ?>">
        <?= htmlspecialchars($flash["pesan"]) ?>
    </div>
<?php endif; ?>

Tips dan Best Practice #

  1. Panggil session_start() di awal — sebelum output apa pun.

  2. Regenerasi session ID setelah login, logout, atau perubahan hak akses: session_regenerate_id(true).

  3. Aktifkan HttpOnly dan Secure pada cookie session.

  4. Set SameSite=Lax atau Strict untuk perlindungan CSRF.

  5. Jangan simpan data sensitif di cookie — password, token rahasia.

  6. Simpan hash token remember me di database, bukan token asli.

  7. Implementasikan timeout session — cek last_activity.

  8. Untuk logout, lakukan $_SESSION = [], hapus cookie, dan session_destroy().

  9. Gunakan session_set_cookie_params() sebelum session_start() untuk konfigurasi keamanan.

  10. Hindari session.use_trans_sid — jangan terima session ID dari URL.

  11. Gunakan session.use_strict_mode = 1 — tolak session ID yang tidak dikenal.

  12. Untuk banyak server, simpan session di Redis atau database — bukan file lokal.

  13. Selalu htmlspecialchars() saat menampilkan data dari session ke HTML.

  14. Hindari menyimpan object besar di session — bisa membebani server dan file session.

  15. Bersihkan session lama secara berkala — PHP melakukan garbage collection otomatis, tetapi bisa dikonfigurasi.

Ringkasan #

Konsep Poin Penting
Cookie Data di browser, dikirim setiap request, maks ~4 KB
Session Data di server, diidentifikasi session ID
setcookie() Membuat cookie — harus sebelum output
$_COOKIE Membaca cookie
session_start() Memulai session — di awal file
$_SESSION Array data session
session_regenerate_id() Regenerasi ID — wajib setelah login
session_destroy() Menghancurkan session
HttpOnly Cookie tidak bisa diakses JavaScript
Secure Cookie hanya via HTTPS
SameSite Perlindungan CSRF

Poin penting:

  • Cookie disimpan di browser, session di server.
  • Session lebih aman untuk data sensitif — data tidak terlihat user.
  • session_start() harus di awal — sebelum output apa pun.
  • session_regenerate_id(true) setelah login — mencegah session fixation.
  • Aktifkan HttpOnly, Secure, SameSite pada cookie session.
  • Untuk logout, hapus $_SESSION, cookie, dan session_destroy().
  • Simpan hash token remember me di database — bukan token asli.
  • Implementasikan timeout session — cek last_activity.
  • Untuk banyak server, gunakan Redis atau database untuk session.
